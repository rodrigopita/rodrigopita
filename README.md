## 🛠️ How I work

**Spec first, code second.** Before building anything non-trivial, I write it down — roadmaps, API specs, domain decisions. Locking the hard decisions early means coding time goes into craft, not re-litigating the design.

**Iterate in small, reviewable steps.** I work in tight loops: build a slice, look at it critically, refine, repeat. Visual details matter to me — if the UI looks careless, the logic probably is too.

**Automate the toil.** If a task is done by hand more than twice, I start designing the pipeline, agent, or integration that makes it disappear. The best compliment my work can get is "I don't have to do that anymore."

**Correctness over cleverness.** Coming from financial data, I default to idempotent pipelines, transactional guarantees, and designs that fail loudly instead of silently drifting.

**Build for real users.** My best projects solve problems for actual people — a sales team that needs data answers, an ops team buried in manual work, a student (me) practicing intervals. Real users keep software honest.
